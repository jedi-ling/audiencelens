# Steam 商店页验证试点手册

## 试点目标

用真实独立游戏项目验证一个窄问题：在 Steam 商店页上线或重大改版前，AudienceLens 是否比单次通用模型和限时人工快评更早发现真人测试随后确认的问题，并促成实际修改。

本试点不验证“替代用户研究”，也不验证所有任务类型。

## 样本与门槛

- 招募 20 个处于商店页草稿、Coming Soon 或重大改版阶段的独立游戏项目。
- 每个项目冻结同一份输入材料，运行三种候选方法。
- 候选输出完成后，再收集至少 10 名目标玩家的盲测反馈或可核查上线结果。
- 至少 5 个团队进入第二次评审，才能初步讨论复购。

在未达到这些门槛前，页面只能展示原始样本数，不能宣传“准确率”或“提升百分比”。

## 每个项目的执行顺序

先创建不会覆盖既有数据的案例目录：

```bash
audiencelens benchmark-init --dir ./pilot-data --case-id studio-001 --title "内部项目名"
```

然后执行：

1. 冻结商店页材料与版本号，记录时间戳。
2. 分别生成 AudienceLens、single-prompt、15 分钟人工快评输出。
3. 记录每种方法的耗时、直接成本和操作者。
4. 三份输出封存后再开展真人盲测，避免参考答案泄漏。
5. 用统一 JSON 契约整理真人反馈。
6. 运行 `audiencelens benchmark-compare`。
7. 团队逐条勾选实际采纳的建议，并填写节省工时与付费意愿。
8. 项目上线或真人测试结束后，在判断账本回填 hit / partial / miss。
9. 累积多个项目后运行 `audiencelens benchmark-suite`。

脚手架默认将 `collected_after_candidates_frozen` 设为 `false`。只有三个候选真正封存、真人参考数据随后收集完成时才能改成 `true`；否则比较命令拒绝评分。

## 统一 single-prompt 基线

为避免故意设置弱基线，单次模型使用与 AudienceLens 相同的模型、相同材料和相近最大输出长度。提示词只能调用一次，不追加追问：

> 你是一名资深独立游戏发行与商店页评审专家。请只依据提供的材料，评估该 Steam 商店页的愿望单吸引力、卖点清晰度、信任信号和价格价值感。输出主要立场、置信度、关键问题、证据和按优先级排列的修改建议。缺失信息必须标记为缺口，不得编造。

完整提示词、模型版本、温度和运行时间必须随候选输出留档。

## 人工快评基线

- 限时 15 分钟；
- 评审者不能查看其他候选结果；
- 使用与机器候选相同的结构化输出字段；
- 记录评审者相关经验，但不记录不必要的敏感身份；
- 人工快评不是最终参考答案，后续目标玩家研究才是。

## 成功标准

进入下一阶段前，至少满足：

| 指标 | 门槛 |
|---|---:|
| 完成项目 | ≥ 20 |
| 每项目真人参考样本 | ≥ 10 |
| AudienceLens 相对 single-prompt 的配对 95% CI | 下界 > 0 |
| 报告有用率 | ≥ 70% |
| 建议采纳率 | ≥ 30% |
| 改变决策率 | ≥ 20% |
| 二次评审团队 | ≥ 5 |

即使质量胜出，如果每条采纳建议成本、交付耗时或复购不成立，也不进入扩张阶段。

## 失败处理

- 若 AudienceLens 与 single-prompt 无显著差异：缩减人格和质询流程，定位无增益环节。
- 若质量更高但采纳率低：优先重做报告可执行性，而不是增加人格。
- 若采纳率高但真人命中率低：停止对外预测性话术，回到头脑风暴定位。
- 若某个任务子类型显著更强：进一步收窄 ICP，而不是平均所有场景。
