⚠ 本文件已作废，请勿引用

架构现状见 docs/ARCHITECTURE.md，能力边界见 README.md。 本文件停留在 2026-07 之前的版本，其中下列声称经代码核验不成立：

  • 测试数 440 / 267 / 173 —— 实际为 688 passed + 1 skipped（引擎 394 + 平台 294，2026-07 实测）。原文"0 skipped / 全绿"抹掉了那 1 项 skipped。
  • 75 个人格 / 8 个 Pack / 5 个红队人格 —— 实际为 72 个人格 / 11 个 Pack，且红队人格包不存在。
  • 三段式交叉质询、投票改票、Δc 改票、共识演化、临界点检测 —— 单轮已实现，其余未实现。cross_exam.py 会真的发出反驳调用（standard 一次仲裁式 / full 逐人格），is_live_debate 按实际结果置位，vote_changes 由代码判定后产出，θ 从 aggregation-rules.yaml 读取；仍不存在的是第 3 轮、提前终止、说服力评分、共识演化与临界点检测。（旧稿称"渲染出的提示词从未发给模型、θ 零读取点"，那是 2026-07 的实况，现已不成立。）
  • "8 维质量门控 / 任一维不达标强制标注" —— Harness 是事后打分卡，enable_evaluation 默认 false，在评审完成之后才跑，不拦截、不过滤、不重跑任何人格输出。
  • 报告示例里的 "伦理评分 72/100"、"Harness 31/40" —— 伦理分为 100 − 10·|违规数|，只能取 10 的倍数，72 不在取值范围内；评估器输出的是 [1,5] 区间的加权均值，不存在 /40 量纲。
  • "越用越准 / 数据网络效应" —— 留档、回填、命中率均已实现，但 hit_rate 没有接回选人或聚合加权，系统不会自动变准。

保留本文件仅为版本留痕。

🔴 做一次真实用户对比验证
P0 必须
目标：拿到 AudienceLens 与真人评审的一致性数据（目标 ≥80%）

这是当前最大短板——SyntheticUsers 靠 85-92% 的一致性数据卖 $60/次，我们没有数据。

操作步骤：
1. 准备评审素材：选一个你熟悉的产品/游戏概念
2. 找 5-10 个真人评审：
  • 朋友/同事/社区成员
  • 让他们回答：最关注的3个问题、评分（1-5）、整体立场（正面/中性/负面）
3. 用 AudienceLens 跑同一素材：
  • 在 Trae 中调用 synthetic-playtest 技能
  • 或直接用 Demo 数据作为基线
4. 运行一致性验证：
  • 将真人数据保存为 JSON 格式（参考 parity_check.py 的输入格式）
  • 运行 python tools/parity_check.py --synthetic <合成报告.json> --human <真人数据.json>
5. 记录结果：综合一致性分数、各维度得分、与 SyntheticUsers 85-92% 基准的对比
🔍 一致性验证脚本 📊 基准测试报告（参考）
