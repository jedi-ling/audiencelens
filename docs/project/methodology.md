# AudienceLens 方法论

AudienceLens 使用合成人格（Synthetic Persona）作为预验证工具。

它不能替代真人 playtest、问卷调查、用户访谈、数据分析或市场研究。

## 方法流程

```text
输入材料
  → 提取假设
  → 选择 persona 面板
  → 独立 persona 评审
  → 交叉质询增强版
  → 合成共识与分歧
  → 运行 Harness 质量检查
  → 一致性验证（tools/parity-check.py）
  → 产出行动计划
```

## 为什么 Harness 很重要

没有质量门控的合成受众系统容易产生：
- 泛泛的赞美
- 浅层的角色扮演
- 刻板印象驱动的反馈
- 无依据的幻觉
- 不可操作的报告

Harness 从 8 个维度检验输出质量，确保评审结果具有实际价值。

## 证据三级标注

每条评审意见必须标注推理层级：

| inference_level | 含义 |
|----------------|------|
| `direct` | 直接来自输入材料 |
| `inferred` | 从输入材料合理推断 |
| `gap` | 材料中无线索，标注"未指定" |

## 行为优先原则

AudienceLens 的核心设计原则是**行为优先于人口统计**：

1. Persona 的判断必须基于 `behavior_profile`，不得将性别/年龄/地域作为偏好的直接因果解释
2. MBTI 仅用于修饰表达风格，不得用于推导核心判断逻辑
3. 人口统计特征仅用于丰富视角多样性，不作为行为推导依据

## 焦点争议点质询

AudienceLens 改进了传统的"让分歧最大的两个 persona 互问"方式：

1. 从所有 persona 输出中提取 top-3 争议点（按 severity 方差排序）
2. 对每个争议点，让持相反立场的 persona 各写一段论证
3. 所有 persona 对每段论证做说服力评分
4. confidence 变化超过 0.15 时允许更新立场

这避免了极端角色的无意义争吵，聚焦于真正有价值的分歧。

## 交叉质询增强版

在焦点争议点质询基础上，交叉质询增强版引入多轮对抗机制：

### 结构化论证阶段
1. **争议点提取**：从所有 persona 输出中提取 top-N 争议点（N 由 depth 参数决定：quick=2, standard=3, full=5）
2. **正反论证**：对每个争议点，持相反立场的 persona 各写一段结构化论证（主张 + 依据 + 推理链）
3. **说服力评分**：所有 persona 对每段论证做 1-5 分说服力评分，并标注推理层级

### 立场更新机制
4. **confidence 漂移检测**：当 persona 的 confidence 变化超过阈值（默认 0.15）时，允许更新立场
5. **立场迁移记录**：记录每次立场变更的 before/after confidence 和触发论证，确保可追溯
6. **收敛判定**：当连续两轮无立场变更时，质询自动终止

### 跨技能适配
- **synthetic-playtest**：聚焦游戏体验争议（玩法、难度、节奏）
- **audience-panel**：聚焦产品价值争议（功能、定价、UX）
- **red-team-audience**：聚焦攻击面争议（安全、信任、边界条件）

## 一致性验证

使用 `tools/parity-check.py` 对合成评审与真人评审进行一致性验证，从四个维度衡量：

| 维度 | 权重 | 说明 |
|------|------|------|
| 主题重叠度 | 0.30 | 合成与真人关注点的一致性 |
| 评分相关性 | 0.25 | 各维度评分的 Spearman 相关性 |
| 立场对齐度 | 0.25 | 正面/负面/中立分布的相似度 |
| 深度对齐度 | 0.20 | 证据详细程度和推理深度的匹配度 |

基准线参考 SyntheticUsers 研究（0.85-0.92 区间）。
