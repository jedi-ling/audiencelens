# 评估器：分段冲突度（Segment Conflict）

检查人格分段之间是否存在有意义的分歧。全员一致的评审面板是可疑的——真实用户群体几乎不会完全同意。

## 评分标准（1-5分）

### 5分 — 丰富冲突
多个维度存在有意义的分段冲突，冲突能够指导产品/设计决策。报告包含"Segment Disagreements"章节，详细描述了对立观点及其背后的行为逻辑。

**通过示例：**
- "核心系统型玩家认为7天生存目标缺乏深度，而休闲型玩家认为7天恰好是合适的承诺时长。"
- "视觉优先型玩家赞赏赛博氛围，但功能优先型玩家认为视觉风格掩盖了玩法信息。"
- "冲突指导决策：如果目标用户是核心玩家，需要增加系统深度；如果是休闲玩家，当前长度合适。"

### 4分 — 明确冲突
存在2-3处有意义的分段冲突，但冲突对决策的指导不够明确。

**通过示例：**
- "硬核玩家和休闲玩家对核心循环深度的期望不同"（有冲突但未说明如何决策）

### 3分 — 基础冲突
存在至少1处有意义的分段冲突。达到最低通过线。

**勉强通过示例：**
- "部分persona认为新手引导清晰，部分认为不够直观"（有分歧但较浅）

### 2分 — 浅表分歧
分歧仅存在于措辞或细节层面，核心观点一致。

**不通过示例：**
- "所有persona都认为需要改善新手引导，只是措辞不同"
- 分歧仅在评分的0.5分差异上

### 1分 — 无冲突
所有 persona 在所有议题上完全一致，像是统一口径。

**不通过示例：**
- 所有 persona 的 primary_stance 相同
- "Segment Disagreements" 章节为空或写"无分歧"
- 所有 persona 的 key_issues 高度重合

## 评估方法

### 定量指标

1. **立场分歧率**：不同 primary_stance 的 persona 占比
   - ≥ 40% 持不同立场 → 分歧充分
   - 20-39% → 分歧一般
   - < 20% → 分歧不足

2. **议题分歧度**：key_issues 的 Jaccard 距离
   - 使用 `compute_coverage_score()` 计算成对 Jaccard 距离
   - 平均距离 ≥ 0.5 → 分歧充分

3. **评分分歧度**：scores 的标准差
   - 任意维度标准差 ≥ 1.0 → 该维度有实质分歧
   - 所有维度标准差 < 0.5 → 无实质分歧

### 定性检查

1. "Segment Disagreements" 章节是否识别了至少1处有意义的冲突？
2. 冲突是否基于行为画像差异（而非随机分歧）？
3. 冲突是否对产品决策有指导意义？
4. 是否存在"冲突解决建议"或"面向不同分段的差异化策略"？

### 综合评分

| 条件 | 分数 |
|------|------|
| 立场分歧率 ≥ 40% + 议题分歧充分 + 冲突指导决策 | 5分 |
| 立场分歧率 ≥ 30% + 有意义冲突 | 4分 |
| 至少1处有意义冲突 | 3分 |
| 仅浅表分歧 | 2分 |
| 无冲突 | 1分 |

## 关键失败条件

- "Segment Disagreements" 章节为空或声称无分歧 → 自动 1分
- 所有 persona 的 primary_stance 完全相同 → 自动 1分
- 所有 persona 的 scores 标准差 < 0.3（所有维度）→ 自动 1分
- 分歧仅存在于措辞而非实质观点 → 该维度 ≤ 2分

## 设计理念

真实用户群体几乎不会在任何议题上完全一致。如果一个评审面板全员同意，说明：
1. 人格差异化不足（参见 persona-differentiation 评估器）
2. 面板选择缺少多样性
3. 评审过程存在趋同偏差

有意义的冲突是评审价值的来源——它揭示了产品决策中需要权衡的取舍。
